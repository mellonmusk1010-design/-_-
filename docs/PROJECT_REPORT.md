## 1. 프로젝트 개요 및 목적

장비나 회선에 장애가 생기면 어떤 대체 경로가 존재하는지 계산하고 장애 전후의 비용과 통신 가능 여부를 비교한다. 사용자는 토폴로지를 편집하고 알고리즘의 한 단계씩을 화면에서 확인할 수 있다.

## 2. SDGs 연계

SDG 9는 예비 회선으로 서비스 연결을 유지하는 인프라 복원력과 연계한다. SDG 11은 재난 상황에서 가상의 병원, 소방서, 재난 상황실에 도달할 수 있는지 비교하는 실험과 연계한다. 학교 예제의 회선 장애는 통신을 유지하지만 경로 비용이 6에서 10으로 늘어난다. 단절 예제에서는 출발지에서 전체 6대 중 3대에 도달하며 지정 목적지의 통신은 복구되지 않는다.

## 3. 자료구조·알고리즘 및 구성

C17 엔진은 배열에 장비 상태를, 인접 연결 리스트에 양방향 회선을 저장한다. 원형 큐는 BFS에서 최소 홉 경로를, 거리 배열은 다익스트라에서 최소 비용 경로를 찾는 데 쓰인다. 스택에는 Undo를 위한 이전 장애 상태를 저장한다. CLI와 WebAssembly가 같은 C 함수를 호출하고, React는 모듈의 결과와 화면 좌표를 SVG에 표시한다. [자료구조](DATA_STRUCTURES.md) · [알고리즘](ALGORITHMS.md)

## 4. 주요 기능과 실행 방법

장비를 추가·삭제하고 위치를 옮기거나 회선 비용을 수정한다. 출발지와 목적지를 지정하고 탐색을 실행한다. 장애를 일으키면 엔진이 대체 경로를 재계산하며 장애 전후 경로와 비용을 나란히 비교할 수 있다. 단계 재생에서 BFS 큐, 다익스트라 거리 배열과 이전 정점 배열을 확인한다. [설치 및 실행 명령](../README.md)

## 5. 테스트와 결과 분석

| 검증 | 실행 결과 |
| --- | --- |
| C17 GCC 빌드 및 C 테스트 | 통과. 정상·단절·복구·동일 정점·잘못된 입력·삭제·중복·큐와 스택 경계 검사 |
| AddressSanitizer·UndefinedBehaviorSanitizer | 통과. 실행한 C 테스트에서 메모리 누수와 정의되지 않은 동작 진단 없음 |
| Emscripten, TypeScript 및 Vite | WebAssembly와 정적 웹 번들 생성 |
| Chromium 통합 | 학교·도시·단절 시나리오와 편집·재생·Undo 검증 |
| Windows 11/WSL | 직접 실행 검증 보류 |

세 가상 예제의 사전 정의 장애를 적용했을 때 목적지까지 연결을 유지한 예제는 학교와 도시 두 건이다. 예제 단위 연결 유지율은 2/3이다. 단절 예제의 장비 도달 가능 비율 3/6은 별개의 지표다. 회선 비용과 장비 도달률은 모의 계산값이다.

## 6. 한계와 개선 방향

장비 슬롯은 최대 32개다. 입력 비용은 단일 양수 정수이며 실제 지연시간이나 트래픽 변화는 모델링하지 않는다. 다음 단계에서는 토폴로지 가져오기·내보내기와 반복 장애 실험을 추가할 수 있다.

## 7. 참고자료 및 AI 활용 내역

Codex를 사용해 설계와 C17·WebAssembly·React 소스 작성, 클라우드 빌드 문제 해결, 테스트 작성 및 실행, 제출 문서 초안을 작성했다. 학생은 자신의 경험을 바탕으로 주제 선정 이유를 작성하고, 직접 재현한 실행 화면과 발표 설명을 보완한다. [참고자료](REFERENCES.md)
